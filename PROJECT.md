# Art’s Workspace Hub — Project Context

AWH is the single operational control plane for the KRUART/BAY ecosystem. Its purpose is to make substantial work durable, auditable, resumable, and safe across web, VPS, optional desktop workers, and managed school products.

## Product boundaries

AWH provides project/source coordination, tasks/executions, approvals, artifacts, automation, health, release control, and operator surfaces. BAY EXCUSE, Assessment, LearnLab, Computer Lab, School Website, BAY Hub, and AWH Agent remain distinct products or capability surfaces; they must reuse canonical identity/work/release boundaries rather than duplicate them.

## Operating principles

- Existing authority first; do not create a second queue, auth store, source authority, approval path, or release controller to bypass a blocked path.
- Mutable truth comes from live evidence, never a prose snapshot.
- Candidate work may be parallel when isolated; conflicting canonical/Production mutations serialize.
- Permanent root-cause fixes and regression evidence are preferred over recurring manual cleanup.
- Owner-facing UI hides engineering complexity by default while retaining diagnostics under progressive disclosure.
