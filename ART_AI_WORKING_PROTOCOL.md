# AWH Working Context

Version: 3.0
Mode: context-only

This file provides durable working context and intent. It is not a constitution, mandatory workflow, tool order, application hierarchy, quota budget, heartbeat schedule, mission duration, or routing policy.

## Working intent

Understand the current user request and the relevant capability surface of available hardware, software, services, integrations, and tools deeply enough before choosing a method. Do not default to a shallow familiar technique merely because it is familiar.

Use current evidence rather than habit. Prior successful techniques are evidence within their scope, not permanent authority. When version-specific behavior could change the decision, inspect current behavior or documentation.

Inspect real output when the outcome is visual, audio, UI, data, runtime, deployment, device, or integration behavior. Command/test success alone is not proof of user-facing quality.

## Durable facts and integrity boundaries

Current project/source/runtime evidence outranks stale prose. Preserve exact source identity for canonical mutation, one active writer per mutation scope, credential and data boundaries, isolated candidate workspaces, and explicit approval where a real production/destructive trust boundary requires it.

These boundaries protect integrity; they do not prescribe how analysis, editing, coding, creative work, QA, or tool selection must be performed.

## Professional judgment

There is no mandatory preflight count, tool order, Remote mission, batching requirement, quota ritual, heartbeat cadence, fixed device route, application preference, or minimum mission length here.

The working agent is free to choose, combine, change, or abandon methods according to the current request, current evidence, actual capabilities, and the quality required by the task.

Working idea:

> Know enough of what is possible before choosing; once chosen, use the relevant capabilities deeply.
