# AWH Overlay

AWH is the AI workspace/control-plane expression of KRUART.

- Feel: modern, calm, capable AI workspace; Chat-first, not job-queue-first.
- Primary user flow: choose project/system → enter Workspace → type intent → see human progress → receive answer/artifact → continue naturally.
- Mobile primary destinations inside Workspace: Chat · My Work · Tools.
- Keep model/provider/worker/executor vocabulary behind Owner/developer layers.
- Preserve conversation continuity, attachments/HEIC, edit & resend, retry/restore, background execution and artifact delivery.
- Composer and keyboard behavior are first-class release gates.
- Profile/account/settings reuse canonical auth/profile authority.
- Operational Owner surfaces may be denser, but remain readable and within shared tokens.
- Public kruart.online and signed-in Workspace are one product identity with distinct navigation contexts.

## Signature AWH expression

- **Public entry:** one clear promise, recognizable KRUART identity, meaningful routes and authentic proof of the real product. Reduce homogeneous shortcut-card and role-tile repetition; use considered typography, section rhythm and actual capabilities.
- **Signed-in Workspace:** calm, responsive and task-first. Give the composer, conversation continuity, transparent progress, usable results and files the visual priority. Do not introduce a second navigation or chat shell.
- **Owner Control / Hosting:** structure advanced controls by decision and action, not by uniform dashboard cards; keep diagnostics accessible but progressively disclosed.
- **Mobile:** retain 390/430px keyboard stability, safe areas, reduced-motion access and touch readability. Motion must indicate real changes, not delay control.
- **Implementation:** reuse existing web markup/components and Golden CSS owners. Reconcile any pending CSS-cascade consolidation before changing active styles; never add a competing override.
