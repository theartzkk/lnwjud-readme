# M17 — AWH Database Studio

Status: isolated implementation branch (`awh/m17-database-studio`)

## Purpose

Database Studio is an Owner-only inspection surface over the existing AWH SQLite control-plane database. It is not a second database authority and it does not introduce a write path.

## Safety contract

- Password-authenticated Owner session only.
- Browser origin policy reused from AWH.
- SQL Console requires a fresh Owner password step-up (15-minute window).
- SQL Console accepts one `SELECT` statement only. `EXPLAIN QUERY PLAN` is generated by AWH rather than accepted as arbitrary input.
- SQLite `PRAGMA query_only = ON` is enabled during raw SQL execution as a second enforcement layer.
- INSERT, UPDATE, DELETE, REPLACE, CREATE, DROP, ALTER, ATTACH, DETACH, PRAGMA, VACUUM, REINDEX, transaction controls, recursive CTEs, file-reading helpers and other high-risk constructs are rejected.
- Credential/session/token/pairing/recovery/rate-limit tables are catalog-visible only as locked entries and cannot be browsed or exported.
- Sensitive columns are redacted from Browse/Audit and excluded from export. Explicit references to those columns are rejected by the SQL Console.
- Browse is capped at 100 rows/page, SQL at 200 rows, export at 5,000 rows and 5 MiB.
- No filesystem path, bearer token, password hash, API credential, pairing code or recovery material is returned to the browser.

## Surfaces

- Overview: SQLite version state, DB/WAL size, page/free-page counts, journal mode, table/row counts, quick check and backup metadata when configured.
- Tables: browse/search/sort/pagination, redaction, Structure, Index and Foreign Key inspection.
- SQL Read-only: SELECT + Query Plan.
- Health: integrity_check and foreign_key_check.
- Migration Center: SQLite user_version, migration ledger and release migration-file hashes.
- Audit: read-only projections of non-sensitive audit tables.
- Export: bounded CSV/JSON from browseable tables with protected columns omitted.

## UI

`web/database.html` is intentionally standalone for the isolated M17 branch so M16 can continue changing the main AWH Work/Settings surface without merge conflicts. The canonical web build emits `database.html`, `database.css` and `database.js`. Main-menu integration should be performed after M16 is committed/rebased.

## Deployment

Production deployment is intentionally not activated in M17 isolation. The existing deployment allowlist/Nginx route must be extended only after M16+M17 integration and normal release QA. ReadyIDC SSH host-key verification remains a separate security gate and must not be bypassed.
